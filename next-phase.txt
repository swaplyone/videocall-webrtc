# Task List – Phase 8 Development

## OTP Verification, Email System, Account Verification, Beta Dashboard & PiP Privacy Protection

### Goal

Build the account-verification, beta-operations, and advanced privacy layer for the standalone Swaply Video Calling Platform.

This phase will provide:

* First-time login verification
* Email OTP verification
* Automated Node.js email sending
* Email verification
* Login security
* Account recovery
* Admin dashboard
* User management
* Email activity monitoring
* OTP abuse protection
* Beta-user management
* Picture-in-Picture privacy protection
* PiP activity monitoring
* PiP capture-risk handling
* Advanced privacy dashboard integration

Reuse the existing Phase 7 privacy event, reporting, blocking, and admin infrastructure wherever possible.

# Module 3: OTP Generation

Create secure OTP generation.

Requirements:

* Cryptographically secure random generation
* 6-digit OTP
* Short expiration
* One-time use
* Server-side validation

Example:

```text
482913
```

Never store OTPs as plain text.

Store a secure hash instead.

# Module 5: First-Time Login Verification

Implement:

```text
Login
  ↓
Credentials valid?
  ↓
First login?
  ├── YES
  │     ↓
  │  Send OTP
  │     ↓
  │  OTP Verification Screen
  │     ↓
  │  Verify OTP
  │     ↓
  │  Login completed
  │
  └── NO
        ↓
     Normal login
```

The first-login verification should be tied to the authenticated login attempt.

Do not consider the account fully verified until the OTP succeeds.

# Module 6: OTP Verification API

Create endpoints:

```text
POST /api/auth/send-otp

POST /api/auth/resend-otp
```

Validate:

* Authentication state
* User identity
* OTP purpose
* Expiration
* Attempt count
* Previous OTP usage

Never accept user-supplied user IDs without verifying them against the authenticated session.

# Module 7: OTP Security

Implement:

### Expiration

```text
OTP lifetime = 5 minutes
```

### Attempts

```text
Maximum attempts = 5
```

### Resend protection

```text
Maximum resend frequency = 1 per 60 seconds
```

### Abuse protection

Rate-limit:

```text
OTP generation
OTP verification
OTP resend
```

Prevent OTP brute force.

# Module 32: PiP Abuse Escalation

When supported capture-risk signals occur during PiP:

```text
Possible Capture Activity
        ↓
Warning
        ↓
Repeated Activity
        ↓
Report / Block
        ↓
Serious Abuse
        ↓
Terminate Call
        ↓
Security Incident
        ↓
Admin Review
```

Do not automatically punish or terminate a user based only on weak browser signals such as:

```text
blur
visibilitychange
tab switching
PiP activation
```

These signals are not proof of screenshot activity.
